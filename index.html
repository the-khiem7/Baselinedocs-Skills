Baseline Docs writes the current truth of your project, its decisions, its evidence and the exact next action into a few files, so a new conversation or another agent can resume without the chat history.Baseline Docs ghi sự thật hiện tại của dự án, các quyết định, bằng chứng và hành động tiếp theo vào vài file, để một cuộc trò chuyện mới hoặc một agent khác làm tiếp mà không cần lịch sử chat.

npx skills add the-khiem7/Baselinedocs-Skills

One command, no account. The skills are folders of Markdown plus a few read-only shell scripts that run on your machine. It needs Node.js for npx.Một lệnh, không cần tài khoản. Skill là các thư mục Markdown cùng vài script shell chỉ đọc, chạy trên máy bạn. Cần Node.js để dùng npx.

A conversation is a poor place to keep the plan. Baseline Docs moves what matters into a small set of files that any later thread, or any other agent, can read in full.Cuộc trò chuyện là nơi kém để giữ kế hoạch. Baseline Docs chuyển điều quan trọng vào một bộ file nhỏ mà mọi thread sau, hay mọi agent khác, đều đọc được đầy đủ.

What a pack is, and where it livesPack là gì và nằm ở đâu

A pack is a set of Markdown files in docs/baseline/<pack-name>/. Every file has one fixed role, and skills write content into the file that owns it. The first three exist in every pack, the last two only when needed.Pack là các file Markdown trong docs/baseline/<tên-pack>/. Mỗi file có một vai trò cố định, và skill ghi nội dung vào đúng file sở hữu nó. Ba file đầu có trong mọi pack, hai file sau chỉ tạo khi cần.

Scope, current truth, target, constraints. Read it to know what the project is.Phạm vi, sự thật hiện tại, mục tiêu, ràng buộc. Đọc file này để biết dự án là gì.

Remember:Ghi nhớ: a pack is internal operational memory. Do not write a pack filename or section into code, configuration or infrastructure resource descriptions. Those strings leave the repository, where the reader has no idea what the file is.pack là bộ nhớ vận hành nội bộ. Đừng ghi tên file hay mục của pack vào code, cấu hình hoặc mô tả tài nguyên hạ tầng. Những chuỗi đó được đưa ra ngoài repo, nơi người đọc không biết file đó là gì.

Work with several domains: initiative and indexDự án nhiều mảng: initiative và index

When work spans dependent domains, each domain gets its own pack and the root folder gets one <initiative>.index.md. The index holds only links, status and dependency edges, and never repeats child content. baselinedocs-onboard reads the index first, then loads one domain pack instead of the whole set.Khi công việc trải qua nhiều domain phụ thuộc nhau, mỗi domain có một pack riêng, và thư mục gốc có thêm một file <initiative>.index.md. Index chỉ chứa liên kết, trạng thái và cạnh phụ thuộc, không lặp lại nội dung pack con. baselinedocs-onboard đọc index trước, rồi chỉ nạp một pack domain thay vì cả bộ.

A typical working dayMột ngày làm việc điển hình

The steps follow the real order of work.Các bước theo đúng thứ tự thực tế của công việc.

  1. StartBắt đầuopen a new threadmở thread mới

    Load the pack into contextNạp pack vào ngữ cảnh

    If the pack exists, open a new thread and load it. Choose onboard for a state report (what the project is, which phase is running, which questions are open, the next step). Choose load to have the agent read it all and answer with one word.Nếu pack đã có, mở thread mới rồi nạp nó. Chọn onboard nếu muốn một báo cáo trạng thái (dự án là gì, phase nào đang chạy, câu hỏi nào còn mở, bước tiếp theo). Chọn load nếu chỉ muốn agent đọc xong và trả lời đúng một từ.

    baselinedocs-onboardbaselinedocs-load
    • No pack yet: init for new work, adopt when a document or spec exists, save when work is underway and nothing is written down.Chưa có pack nào: dùng init cho việc mới, adopt khi đã có tài liệu hoặc spec, save khi đã làm dở mà chưa ghi gì.
    • Both skills read every file in the chosen scope and write nothing. If the scope is too large the agent stops and proposes a narrower one rather than reading half.Cả hai skill đọc đủ từng file trong phạm vi đã chọn và không ghi gì. Nếu phạm vi quá lớn, agent sẽ dừng và đề nghị thu hẹp thay vì đọc nửa chừng.
  2. WorkLàm việcfollow the roadmaptheo roadmap

    Run phase by phaseChạy từng phase

    run executes the roadmap phase by phase and writes a checkpoint into the roadmap after each one. Before it starts it asks you two things and never picks a default: pause after each phase, and commit each verified phase. Choosing per-phase commits is your authorization to commit in that run.run thực hiện roadmap theo từng phase và tự ghi checkpoint vào roadmap sau mỗi phase. Trước khi bắt đầu, nó hỏi bạn hai điều và không bao giờ tự chọn mặc định: có tạm dừng sau mỗi phase không, và có commit mỗi phase đã xác minh không. Chọn commit theo từng phase chính là bạn cho phép commit trong lần chạy đó.

    baselinedocs-runsync-codebase
    • Code changed or a phase ended and the docs may be stale: the agent may call sync-codebase to pull the documents back in line with the code.Code đổi hoặc phase kết thúc mà tài liệu có thể lỗi thời: agent có thể tự gọi sync-codebase để kéo tài liệu về khớp với code.
  3. When something changesKhi có thay đổiclose, open, movechốt, mở, dời

    Write down what a checkpoint does notGhi lại điều checkpoint không ghi

    A run checkpoint records only the phase result. If you just closed a decision, opened a question or moved scope, run save. It writes what the thread established into the right pack file.Checkpoint của run chỉ ghi kết quả phase. Nếu vừa chốt một quyết định, vừa mở một câu hỏi mới, hoặc phạm vi đã dời, chạy save. Skill này viết điều thread đã xác lập vào đúng file của pack.

    baselinedocs-savebaselinedocs-adrsync-decisions
    • A decision that matters outside the repository: adr drafts a standalone ADR in docs/adr/, always with status Proposed. To have the pack record that the ADR exists, run save.Quyết định đủ quan trọng với bên ngoài repo: dùng adr để soạn một ADR riêng trong docs/adr/, trạng thái luôn là Proposed. Muốn pack ghi nhận ADR đó tồn tại thì chạy save.
    • Two documents contradict each other: the agent uses sync-reconcile to repair it. onboard only reports.Hai tài liệu mâu thuẫn nhau: agent dùng sync-reconcile để sửa. onboard chỉ báo, không tự sửa.
  4. Context fullNgữ cảnh đầythe window is nearly outcửa sổ sắp hết

    Always save before you branchLuôn save trước khi rẽ nhánh

    Whether you stay in the thread or open a new one, the conversation loses part of itself. Only the pack stays whole, so save comes before any choice.Dù ở lại thread hay mở thread mới, cuộc trò chuyện đều mất một phần. Chỉ pack là còn nguyên, nên save đi trước mọi lựa chọn.

    baselinedocs-save
    • Open a new thread (the default once the pack is current): after save, the pack is the only source of truth. The new thread runs onboard or load.Mở thread mới (mặc định khi pack đã mới): sau save, pack là nguồn sự thật duy nhất. Thread mới chạy onboard hoặc load.

Rules for working with a packQuy tắc khi làm việc với pack

A pack is current operational memory, not a log of commands that ran. These rules keep it quick to read and worth trusting.Pack là bộ nhớ vận hành hiện tại, không phải bản ghi các lệnh đã chạy. Mấy quy tắc này giữ cho nó đọc nhanh và đáng tin.

DoNên

Record the final evidenceGhi bằng chứng cuối cùng

The final pass or fail supports current status. Keep an intermediate failure only if it is still actionable, explains a design change, or reproduces a defect.Kết quả pass hoặc fail cuối đỡ cho trạng thái hiện tại. Giữ lại lỗi trung gian chỉ khi nó còn cần xử lý, giải thích vì sao thiết kế đổi, hoặc tái hiện một lỗi.

DoNên

Fold small corrections into the earlier phaseGộp chỉnh sửa nhỏ vào phase cũ

Open a new phase only for a distinct outcome, dependency, release gate or independently reviewable scope. Otherwise the roadmap becomes a change log.Chỉ mở phase mới cho một kết quả, phụ thuộc, mốc phát hành hoặc phạm vi cần review độc lập. Nếu không, roadmap sẽ thành nhật ký thay đổi.

DoNên

Write the reason with the decisionGhi lý do cùng với quyết định

For each decision: what was decided, why, what breaks if ignored, which alternatives were rejected and why. A rejected option that is not written down gets proposed again.Mỗi quyết định ghi: đã chốt gì, vì sao, hỏng gì nếu bỏ qua, phương án nào bị loại và lý do. Phương án bị loại mà không ghi sẽ bị đề xuất lại.

DoNên

Move reusable procedures to the wikiĐưa quy trình dùng lại vào wiki

A pack holds one task's state. A procedure useful across tasks lives in docs/wiki/<topic>.md, and extract-wiki does the move.Pack giữ trạng thái riêng của một task. Quy trình dùng được cho nhiều task nằm ở docs/wiki/<chủ-đề>.md, và extract-wiki làm việc chuyển đó.

Do notKhông

Edit a pack by line numberSửa pack theo số dòng

Line numbers go stale after the first write. Anchor every change on text that occurs once, such as an entry heading.Số dòng cũ ngay sau lần ghi đầu tiên. Neo mọi thay đổi vào một đoạn văn bản duy nhất, như tiêu đề của một entry.

Do notKhông

Hard-wrap paragraphsNgắt dòng cứng trong đoạn văn

One paragraph is one line, however long. Hard wrapping splits a paragraph into fragments and breaks every line-number reference.Một đoạn là một dòng, dù dài. Ngắt dòng cứng làm đoạn văn vỡ thành những mảnh rời rạc và làm sai mọi tham chiếu số dòng.

Do notKhông

Put pack identifiers in commit messagesĐưa mã pack vào commit message

A commit outlives the pack and its reader cannot open it. An entry or phase code would point at nothing.Commit tồn tại lâu hơn pack, và người đọc nó không mở được pack. Một mã như entry hay phase sẽ không trỏ tới đâu cả.

Do notKhông

Let the agent pick the policyTự chọn chính sách cho agent

Approval after each phase and committing each phase are yours to decide. run will ask, and you need to answer explicitly.Phê duyệt sau mỗi phase và commit mỗi phase là việc bạn quyết. run sẽ hỏi, và bạn cần trả lời rõ ràng.

Every pack document carries frontmatter with baseline_schema, pack, document, status, updated and code_ref. updated is the date of the last edit. code_ref is the code state actually inspected. A newer commit is a signal of drift, not proof.Mỗi tài liệu pack có frontmatter gồm baseline_schema, pack, document, status, updated và code_ref. updated là ngày sửa tài liệu lần cuối. code_ref là trạng thái code thực sự đã được kiểm tra. Commit mới hơn chỉ là tín hiệu lệch, chưa phải bằng chứng.
